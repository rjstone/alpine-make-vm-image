This project provides a script for making customized https://alpinelinux.org/[Alpine Linux] VPS qcow2 images for Digital Ocean "Droplets" (their brand name for their VPS service instances). They are built for BIOS boot using https://www.gnu.org/software/grub/[GRUB] (not Syslinux: see `--bootloader` in the script), x86_64, install `cloud-init`, `gcompat`, and otherwise only the bare minimum stuff needed.

This is a fork of the {gh-name} repo which has a different default branch for the DO image build, and this different readme, but is otherwise the same as {gh-name}.

== Logging In

Your options for initial login are:

- Use the recovery console and login as `alpine`: The user `alpine` needs no password on the console (its password is locked, and not asked for there even if you set one later), but it is restricted to only logging in on the console; ssh etc is blocked. From here you can use passwordless `doas` to add ssh keys to root, create users, etc., but `alpine` is blocked from ssh login in 3 places.

- You can boot the image with no user-data and cloud-init will still install your web UI or cli-selected Digital Ocean keys for the root user. Root user login is blocked on the console by default, but is allowed on console if a password is set. root ssh is allowed with keys, but not with a password even if it is set.

- Or use your own cloud-init user-data.yaml to set up accounts and keys however you want when its supplied on droplet creation.

See the documentation linked below for more extreme detail.

A short quick start for using the image if you have doctl CLI set up (install the doctl package and use `doctl auth init` with a personal access token if not):

[source,bash]
----
doctl compute region list
doctl compute image create alpine-latest --image-url https://github.com/rjstone/alpine-make-vm-image/releases/download/image-latest/alpine-do.qcow2.bz2 --region <region slug(s)>
doctl compute image list-user
doctl compute ssh-key list
# if needed: doctl compute ssh-key import --public-key-file <file>
# note that you may need to specify image ID rather than slug for custom images
# ssh keys probably need ID as well
doctl compute droplet create --image XXXXXXXXX --region SFO3 --size s-1vcpu-512mb-10gb --ssh-keys 39974029 --tag-name delete-me-just-testing --user-data-file your-user-data.yaml --wait alpine-test-droplet-delete-me
----

and confirm you can `ssh root@<ip>`, that `df -h /` shows the full 10 GiB (growpart
worked), and that user-data succeeds.
